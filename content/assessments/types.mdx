# Assessment Types

AceInt provides three assessment formats to help evaluate candidates at different stages of your hiring process.

Choosing the right assessment type helps improve hiring accuracy, reduce evaluation time, and provide a better candidate experience.

Available assessment types include:

- Coding Challenges
- Multiple Choice Questions (MCQ)
- Mixed Assessments

Each format is designed for a different hiring objective.

---

## Coding Challenges

Coding assessments contain one or more programming problems that candidates solve in AceInt's browser-based code editor.

Each coding challenge includes:

- Problem statement
- Constraints
- Visible test cases
- Hidden test cases
- Starter code (optional)

Candidates can run their code against visible test cases before submitting.

After submission, AceInt's AI grading engine evaluates the solution across four dimensions:

- Correctness
- Code Quality
- Algorithmic Efficiency
- Completeness

Every coding question receives a score between **0 and 100** within seconds.

Candidates can choose their preferred programming language unless the assessment restricts available languages.

---

## Multiple Choice Questions (MCQ)

MCQ assessments present candidates with timed questions containing between **2 and 6 answer choices**.

Questions may have:

- One correct answer
- Multiple correct answers

MCQs are graded instantly by comparing submitted answers with the configured answer key.

Because no AI grading is required, results are available immediately after submission.

MCQs are ideal for evaluating:

- Programming fundamentals
- Framework knowledge
- SQL
- System Design
- Networking
- Security
- Cloud concepts
- General technical knowledge

---

## Mixed Assessments

Mixed assessments combine coding challenges and MCQ questions within a single assessment.

Candidates complete both question types during one session.

Questions can be presented:

- In a fixed order
- In a randomized order

The final assessment score is calculated using the weighted scores of every question.

You can assign different point values to each question, allowing coding challenges to contribute more heavily than conceptual MCQs if desired.

Mixed assessments reduce the number of interview rounds while providing a broader evaluation of technical ability.

---

## Comparison

| Assessment Type | Best For | Grading Method | Typical Duration |
|-----------------|----------|----------------|------------------|
| Coding Only | Deep technical evaluation, senior hiring, take-home replacement | AI Grading | 30–90 minutes |
| MCQ Only | High-volume screening, knowledge verification | Instant Scoring | 10–30 minutes |
| Mixed | Complete technical evaluation in one round | AI + Instant Scoring | 45–120 minutes |

---

## When to Use Coding Challenges

Choose **Coding Challenges** when you need to evaluate how candidates actually write software.

Recommended for:

- Senior engineering positions
- Backend development roles
- Frontend development roles
- Full-stack interviews
- Replacing take-home assignments
- Evaluating problem-solving ability
- Reviewing code quality and efficiency

Coding assessments provide the deepest technical insight.

---

## When to Use MCQ Assessments

Choose **MCQ assessments** when speed and scalability are the priority.

Recommended for:

- Large candidate pools
- Campus hiring
- Initial screening rounds
- Technology knowledge verification
- Certification-style assessments
- Non-coding technical roles

MCQs provide immediate results and require no AI grading time.

---

## When to Use Mixed Assessments

Choose **Mixed assessments** when you want to evaluate both theoretical knowledge and practical coding skills.

Recommended for:

- Mid-level engineers
- Senior engineers
- Full interview rounds
- Technical hiring with limited interview stages

Mixed assessments help reduce the number of separate interview rounds while providing a more complete picture of candidate ability.

---

> **Tip**
>
> A common hiring strategy is:
>
> 1. Use an **MCQ assessment** to quickly screen a large number of candidates.
> 2. Invite shortlisted candidates to complete a **Coding Challenge**.
>
> This approach saves time for both recruiters and candidates while keeping technical evaluations focused on the strongest applicants.
