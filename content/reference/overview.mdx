The AceInt API is a RESTful HTTP API that lets you programmatically manage candidates, run AI-powered interviews and assessments, retrieve results, and configure webhooks. Every response body is JSON, and all write operations accept a JSON request body.

## Base URL

All API requests target a single versioned base URL:

```bash
https://api.aceint.dev/v1
```

Include this prefix before every path shown in the endpoint pages. There is no trailing slash.

## Authentication

Authenticate each request by passing your secret API key in the `Authorization` header:

```bash
Authorization: Bearer YOUR_API_KEY
```

Generate and manage keys from **Settings → API Keys** in the AceIntdashboard. Each key carries one or more permission scopes that control which endpoints it can reach. See the [Authentication](/reference/authentication) page for the full setup walkthrough, scopes reference, and security best practices.

## Content Type

Set `Content-Type: application/json` on every request that includes a body (`POST`, `PATCH`). Requests that send data without this header return a `400` error.

## Versioning

The current stable version is **v1**, encoded directly in the base URL. When breaking changes are introduced, a new version path is released and the previous version is deprecated with at least 90 days notice. Non-breaking additions — new optional fields, new endpoints — are made to the current version without a version bump.

## Quick Start

The following `curl` command retrieves your first page of candidates and confirms your key is working:

```bash
curl https://api.aceint.dev/v1/candidates \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Accept: application/json"
```

A successful response returns HTTP `200` with a JSON body like the one described in the next section.

## Response Envelope

Every successful response wraps its payload in a `data` key. Collection endpoints add a `meta` object with pagination information.

**Single resource**

```json
{
  "data": {
    "id": "cand_01hx4z",
    "name": "Jordan Lee",
    "email": "jordan@example.com"
  }
}
```

**Collection**

```json
{
  "data": [
    { "id": "cand_01hx4z", "name": "Jordan Lee" },
    { "id": "cand_01hx50", "name": "Sam Rivera" }
  ],
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 150
  }
}
```

Use `meta.page`, `meta.per_page`, and `meta.total` to implement pagination across all list endpoints.

## Error Format

When a request fails, AceIntreturns a descriptive error object instead of a `data` payload:

```json
{
  "error": {
    "code": "validation_error",
    "message": "The email field must be a valid email address.",
    "field": "email"
  }
}
```

`code` is a machine-readable string you can switch on in your error-handling logic. `message` is a human-readable explanation. `field` is included when the error is tied to a specific request parameter.

## HTTP Status Codes

| Status | Meaning |
| --- | --- |
| `200 OK` | Request succeeded. Response body contains the requested data. |
| `201 Created` | Resource created successfully. Response body contains the new resource. |
| `400 Bad Request` | Invalid request syntax, missing required field, or failed validation. |
| `401 Unauthorized` | Missing or invalid API key. |
| `403 Forbidden` | API key is valid but lacks the required scope for this operation. |
| `404 Not Found` | The requested resource does not exist. |
| `429 Too Many Requests` | Rate limit exceeded. Back off and retry. See [Rate Limits](/reference/rate-limits). |
| `500 Internal Server Error` | Unexpected server-side error. Retry with exponential backoff. |
